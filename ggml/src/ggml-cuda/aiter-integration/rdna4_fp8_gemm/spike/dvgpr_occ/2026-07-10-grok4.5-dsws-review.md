## 1. What I like (only where it informs a recommendation)

- **Flood / no-poll hot path** is the right response to the measured FOLLOW_WAIT disease. A mailbox that is always a valid role makes lag free by construction (`occ_kernel_dsws_flow.s:1615–1620`).
- **compute→feed coast as a code-path flip** (no `s_alloc_vgpr`) is the highest-leverage correctness/perf idea in the design, and the emitted VGPR map supports it (see §3.3).
- **Single-writer ASSIGN / ROLE / STAMP-reset** plus **monotone CAS** on STAGE/DRAIN is the only barrier-free pattern that can work on this ISA. Keep it; do not reintroduce multi-writer elections.
- **SAFEPROBE ti/group clamps** (`DECODE_STI` + `s_min` on group at `occ_kernel_dsws_flow.s:1665–1668`) correctly internalize the Phase-B OOB lesson. Any new decode path must get the same clamp.
- **POOL_N=1 for group-split bring-up** is the right serialization: it removes H1/H5-class bank races while you debug completion.

## 2. Highest-severity findings

### 2.1 Run-6 signature is a *completion-class* hang; pure staging-protocol deadlock is weakly supported by source + offline models

**Evidence**

| Observation (brief §6) | Implication |
|---|---|
| `ACC_N=6` clean; `ACC_N=3` hangs | Group-split codegen is implicated |
| `occ0=0` from **+0.2s** | All waves that ever `live++` also `live--`, **or** no wave ever entered (`live++` is after lean alloc at `:1443–1454`) |
| Deadman default 50M ticks ≈ 0.5s | Early `occ0=0` is **faster than deadman** if RTC≈100 MHz as claimed |
| `fence=--` for the full host timeout | Something never delivered a clean EOP |

**Offline protocol model (I wrote/ran):** 16 threads, `GROUPS=2 ACC_N=3`, full-G A staging (as source does), `memory_order_relaxed` atomics for all LDS-like words, seed roles matching `:1470–1484`. **Result: 0/200 stuck; all trials reached `FLOWTERM` + `DRAIN==ASSIGN==SUPER`.**

**Sequential model:** full-G A + STAGE gate `ARDONE≥G` completes. Staging only `ACC_N` A rows while STAGE still wants `G` **deadlocks immediately** (see §2.2) — but that is *not* the current source.

**Source-supported ranking of the three §6 hypotheses**

| # | Hypothesis | Support from source / offline | Confidence |
|---|---|---|---|
| 1 | **Exit / EOP path** (`RETBARRIER` / staggered `s_endpgm` / never-`live++`) | Best match to `occ0=0` + `fence=--`. `RETBARRIER` (`:1931–1947`) has **no deadman**, only `RETBAR_MAX`. `live--` happens *before* the retbar wait (`:1919–1927`). | **Medium-high** |
| 2 | **Completer/DRAIN single-winner hazard** | After `SL_RBDONE` hits `ACC_N`, **only that wave** advances DRAIN (`:1775–1825`). Between `RBDONE++` and DRAIN CAS there is an **unbounded** `s_alloc_vgpr 32` shrink spin (`:1779–1781`) with no deadman. If that unique wave never reaches `lds_cmpstore_adv`, DRAIN freezes forever while others only take the exhausted-`RBNEXT` path (`:1659–1660` → `:1826–1833`) and **never retry DRAIN**. Protocol model assumes atomic “rbdone then drain”; real ISA can split them. | **Medium** |
| 3 | **Staging deadlock (coast never finishes BF/AR)** | Possible on hardware (LDS visibility / starvation), but **not reproduced** in relaxed multi-thread model; coast path exists and is free for fat→lean feed (`:1882–1917`). Weaker as the *primary* story for `occ0=0@0.2s`. | **Low-medium** |

**Fourth mechanism (not in §6 list):**  
**`occ0=0` because waves never `live++`** — permanent spin in `.Lflow_alloc` (`:1443–1446`). That produces `occ0=0` + no EOP without any frontier work. Unlikely to be group-split-specific at fixed `VBUDGET`/`WAVES` (LDS 33024 still 1 WG/CU), but Run 8’s frontier line would stay at zeros and would *not* prove staging — treat “all-zero FRONTIER + occ0=0” as **pre-init/alloc**, not pipeline freeze.

**Offline experiment to refine before/with Run 8**
1. Keep my `/tmp/test_flow_groupsplit` model; add an explicit “completer dies after rbdone++” injection → must hang (documents hazard).  
2. Assemble `DEADMAN=1 STAGINSTR=1 ACC_N=3`; disasm-confirm `deadman_check` is **absent** from `.Lflow_bshrink` / `.Lflow_retbar`.  
3. On GPU (when greenlit): if last FRONTIER shows `RBDONE≥ACC_N`, `BF≥FN`, `AR≥G`, `DRAIN<ASSIGN` → hypothesis 2. If `barrier>0` and `ASSIGN` advanced then stopped with waves retired → hypothesis 1. If all heads 0 → fourth mechanism.

### 2.2 Group-split A-side is intentionally still whole-tile; half-applying the edit map will hang

**Source**

- Compute claims **local** `0..ACC_N-1` and maps `actual_rowblk = group*ACC_N + local` (`:1658–1689`).
- Completer / RBDONE target is **`ACC_N`** (`:1784–1804`).
- `ASTAGE_R` still claims **`r ≥ G` bail** and stages absolute rowblks `0..G-1` (`:756–790`).
- STAGE advance still requires **`ARDONE ≥ G`** (`:1872–1875`).
- Comments at `:365` / `:369` still say “≥ G” for RBDONE — **stale comments** (code uses `ACC_N` for RBDONE).

**Offline**

- Full-G staging + `ARDONE≥G` → completes.  
- Stage only `ACC_N` A rows + gate still `G` → **STUCK at first super-tile** (Python model).

**Finding:** Current code is internally consistent (wasteful A traffic × `GROUPS`, but not a staging deadlock by construction). The morning edit map’s “feed banks LOCAL 0..ACC_N-1” is **not what landed** for A. If someone “finishes” that edit without also changing the STAGE gate (and ARES layout) to `ACC_N`, you will manufacture the staging deadlock §6 fears.

**Confidence:** High (source + offline model).

**Offline experiment:** Any patch that changes `ASTAGE_R` claim limit to `ACC_N` must be rejected by a unit model unless STAGE’s compare and ARES indexing change in the same patch; assemble + grepping for `s_cmp.*ACC_N` vs `G` on the ARDONE path.

### 2.3 `RETBARRIER` is load-bearing for WAVES=16 EOP, but is a footgun

**Source (`:330–335`, `:1467–1469`, `:1931–1947`)**

- Count-to-`WAVES` on **`QUIESCE_CNT_OFF`**, which is the **Phase-B** symbol at byte **96** (`ROLE[19]` in the flow mailbox reservation). Safe for `WAVES≤16` (roles use `0..15` only; coord state at 140/144), but it is an **alias**, not a dedicated flow field.
- `live--` then wait; **no `deadman_check`** on `.Lflow_retbar`.
- Escape is `RETBAR_MAX=1e6` × `s_sleep SLEEPN` — wall time depends on sleep implementation; at pessimistic cycle costs this can approach host-timeout scale (I estimated ~0.04s–40s depending on per-iter cost). That is exactly the shape of “`occ0=0` forever, fence eventually/never.”

**Confidence:** Medium-high on the structural issue; medium on it being Run 6’s root cause.

**What I would change**

1. Dedicated `FLOW_RETBAR_OFF` in the flow control region (not Phase-B `QUIESCE_CNT_OFF`).  
2. `deadman_check` (or a much smaller `RETBAR_MAX`) on the retbar spin so a completion hang **drains to `s_endpgm` quickly** without relying on MES.  
3. Host: if `occ0==0 && fence==--` for >N ms, print retbar word + “likely exit-path.”

**Offline experiment:** Assemble `RETBARRIER=0` vs `1` (sizes/sha); CPU model of retbar with delayed LDS visibility; on GPU (greenlit) compare EOP for WAVES=16 whole-tile (already known needing retbar per comment).

### 2.4 Unique-completer window after `RBDONE++` is a real structural deadlock class

**Source order on the compute success path (`:1774–1825`):**

1. `instr_inc` (optional)  
2. `SL_RBDONE` fetch-add → this wave may become the unique completer  
3. `fat_dec`  
4. **`.Lflow_bshrink`: `s_alloc_vgpr 32` until SCC1** — unbounded, no deadman  
5. Only then: “am I completer?” → optional C-store → `lds_cmpstore_adv DRAIN`

No other wave will advance DRAIN if this wave never returns. Exhausted claimers only branch to `.Lflow_cmp_tryadv` / loop.

This is **not group-split-specific**, but group-split multiplies super-tiles (`GROUPS×n_kseg` assigns per tile), so any rare shrink/glitch is more likely to be hit in a long run. It also means Run 8’s “RBDONE full, DRAIN stuck” verdict is a **first-class** expected pattern, not an exotic.

**Confidence:** High that the hazard exists; low-medium that it alone explains Run 6.

**Fix direction (offline-checkable):** After `RBDONE` reaches `ACC_N`, **any** wave that observes `RBDONE≥ACC_N && DRAIN==slot_index` may CAS-advance DRAIN (idempotent), and/or move shrink **after** DRAIN CAS for the completer. Discriminator: CPU model with “completer stuck in shrink” must hang today and pass after the change.

## 3. Group-split mechanism review (packing, C-base, occupancy lever)

### 3.1 STAMP packing and C-base — correct as emitted

**Disasm `ACC_N=3` (GROUPS=2) confirms:**

| Item | ISA / immediate | Source |
|---|---|---|
| `GKSI_MAX = GROUPS<<shift` | `s_lshl_b32 s46, 2, s68` | `:1535` |
| STI strip | `s_and_b32 s17, s17, 0xfffffff` **4×** (compute + feed + 2× coast) | `:1669`, `:1850`, `:1903–1913` |
| Group C offset | `s_mul_i32 s39, s41, 0x6000` (= `ACC_N*FM*FN*1024` = 24576) | `:1799` |
| Tile C stride | `s_mul_i32 s38, s38, 0xc000` (= `G*…` = 49152) | `:1795` |
| ACC_N=6 | **0** STI_MASK immediates (GROUPS=1 paths dropped) | byte-identity claim support |

Collision-free for `group ∈ [0,GROUPS)`: group `g` owns C bytes `[g·ACC_N·8192, (g+1)·ACC_N·8192)` inside the tile’s `G·8192` region. SAFEPROBE `s_min s41, GROUPS-1` prevents OOB C-base from torn STAMP.

**Confidence:** High.

**Offline experiment already done:** disasm immediates; rebuild ACC_N=6 twice → `cmp` identical.

### 3.2 Occupancy lever is weaker than the narrative (and incomplete)

Resident LDS (SEGK=32, POOL_N=1) from the same formulas as the kernel:

| ACC_N | LDS | WG/CU (64KB) | Notes |
|---|---|---|---|
| 6 | 57600 | 1 | whole-tile |
| 3 | 33024 | **1** | group-split **does not yet buy a second WG** |
| 2 | 24832 | **2** | first real occupancy win |
| WOFLUSH-like (0 ACC banks, full ARES) | ~8448 | **7** | alternative lever already in tree (`WOFLUSH`) |

**ARES is still `G`-sized** (`ARES_BYTES = G*16*FM*SEGK` at `:279`). Group-split only shrinks **accumulator banks**. So ACC_N=3 is a correctness stepping-stone, not the occupancy win. The brief’s “ACC_N=3 → 2 WG/CU” table in spirit matches ACC_N=2 in the morning doc; do not expect bind-threshold movement at ACC_N=3.

**Alternatives to get the dyn-VGPR pool to bind (goal: more concurrent fat waves, B-reuse retained):**

1. **Finish group-split on ARES** (stage only group’s `ACC_N` A rows into a shrunk ARES; STAGE gate `ARDONE≥ACC_N`; B still re-scanned per super-tile from L2). Bigger LDS win than ACC alone.  
2. **`WOFLUSH=1`** (burst atomic C) — largest LDS cut; trades write-once for atomic C traffic (known; use as occupancy probe, not final).  
3. **More WGs via smaller POOL / SEGK** already partially used.  
4. **Do not** chase higher occupancy until ACC_N=3 **completes clean** — occupancy multiplies hang surface.

**Confidence:** High on math; medium on which lever is best after correctness.

### 3.3 Coast safety (VGPR / OOR / exec) — OK as emitted

- Lean temps: `RG_*/RP_* = v11/v14` under `DYNVGPR` (`:415–419`); feed staging `BSTG=16` (`:411`); `NFV=112` with `ACC` at v32+ (`:406–409`).  
- Coast enters feed macros only when grow failed or stage empty **before** grow (`:1643–1644`, `:1653–1655`) → wave is lean.  
- Role-adopt path only **shrinks** (`:1627–1630`); per-burst grow is inside compute.  
- LDS atomics are lane0-masked with exec restore (`:481–505`).  
- Group STAMP strip present on all coast/feed DECODE sites (disasm 4× `0xfffffff`).

**Confidence:** High for “no OOR temp on coast path as written.” Residual: fat wave mid-burst cannot coast without shrink (by design); deadman mid-burst would retire without shrink (pool poison) — separate issue, same for all ACC_N.

**Offline experiment done:** disasm + static VGPR map; optional: RGA livereg on ACC_N=3 (brief already reports max used 85).

## 5. Unvetted code review (Phase-B SENSOR FIX / OCCA_PUB + flow exit/seed)

### 5.1 SENSOR FIX + `OCCA_PUB_OFF` (Phase-B)

**What it does:** Claimer tracks mid-drain peak in `s73/s74`, publishes to `OCCA_PUB`/`OCCB_PUB` (`occ_kernel_dsws.s:1312–1325`); followers decide on **published** peaks (`:1463–1464`, `:1543–1544`, `:1783–1784`) instead of post-drain `occ_sample≈0`.

**Verdict:** The failure mode it fixes (always-starved → compute→feed runaway) is real and well-commented. Seed `OCCA_PUB=2` (`:1139`) sits strictly between `CTRL_LOW=1` and `CTRL_HIGH_*` — neutral. Publish without `s_wait_dscnt` is intentional (consumed next epoch).

**Risks / nits**

1. **First epoch** after init uses seed=2 only — fine.  
2. Publish is **not** atomic with epoch bump; followers can tear a peak word — one-epoch wrong mix, not a hang (mix is soft-state).  
3. Layout: `OCCA_PUB` at byte 100 is in the Phase-B control gap **below** `BRES_OFF=256` — OK for Phase-B; **do not** assume these offsets are free in the flow LDS map (flow reuses low bytes for frontiers).  
4. DIAG wedge frame (`:1330–1377`) is good; keep it throttled if ever combined with long spins (Run 7 lesson).

**Confidence:** Medium-high that SENSOR FIX is directionally correct; high that it does not affect the flow group-split hang (different kernel).

### 5.2 “Every non-claimer bails exactly once per super-tile” (Phase-B)

**Source structure:** Each of `.Lbfeed` / `.Lafeed` / `.Lcompute` has a single `_quiesce` tail that bumps `QUIESCE_CNT` once per epoch after work (`:1477–1482`, `:1557–1561`, `:1804–1810`). FORCE paths are if/else with the normal watermark path, not an extra bump.

**Skip/double risks**

- **Skip:** wave stuck before bail (alloc / follow / mid-work) — straggler model shows permanent block → 100% stall, gate `s50`.  
- **Double:** would require taking two role quiesce paths in one epoch without epoch advance — not in the control flow as written.  
- **Claimer** does not bail into `QUIESCE_CNT` (want `WAVES-1`) — correct.

**Flow kernel:** no per-super-tile bail; exit is one `live--` + retbar per wave. Deadman and ROLE_RETIRE share `.Lflow_retire` — single exit.

**Confidence:** High for “one bail per epoch when the wave reaches quiesce”; medium that hardware never double-fires (would need ISA-level re-exec evidence).

### 5.3 Monotone frontiers + single-writer vs never-reset counters

**Flow’s resettable slot counters** are safe **only if** the free gate `ASSIGN−DRAIN < POOL_N` is respected and STAMP/counters are published before consumers observe ASSIGN. Same-wave program order on the coordinator is fine; cross-wave, consumers can see ASSIGN early and STAMP late — mitigated by SAFEPROBE clamps (wrong tile, not OOB).  

**Coop-style never-reset counters** (`epoch * expected`) avoid reset races entirely and were battle-tested on this target. I would **not** rewrite flow mid-hang-hunt, but if group-split remains flaky after frontier localization, a **monotone global super-tile id + expected RB/BF/AR totals** (no per-slot zeroing) is the higher-assurance primitive.

**Confidence:** Medium (design judgment).
