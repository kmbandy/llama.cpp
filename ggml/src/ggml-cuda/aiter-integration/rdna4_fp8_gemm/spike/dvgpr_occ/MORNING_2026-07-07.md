## WHAT THE GROUP-SPLIT IS (the thing being debugged)

**Goal (kmbandy's exact framing):** *reduce LDS footprint but RETAIN B reuse so we don't reintroduce fetch
lag.* The occupancy lever for Step 2. My morning spec-rewrite (DSWS_GRESIDENT_DESIGN.md v2, Fable's whole-tile
deferral) was WRONG for this goal — the group-split IS the lever.

**Mechanism:** decouple `G`(=6 rowblks/tile) from `ACC_N`(=banks=group size). `GROUPS = G/ACC_N` **sequential**
passes reduce the tile's rowblks through `ACC_N` LDS banks. `ACC_N<G` shrinks resident banks (`ACC_N·8192` vs
`G·8192`) → more WGs/CU → the dyn-VGPR pool can finally bind. Each group **re-scans `B[:,tcol]`**; the feed
already re-stages B per emitted super-tile, so emitting `(tile,group,ksi)` super-tiles gives the per-group B
re-scan **for free**, and since the whole B column stays warm in L2 (measured L2=8MB), the re-scan is an **L2
hit, not HBM** → B-reuse retained, no fetch lag. `POOL_N=1` keeps groups strictly sequential (group g stores +
recycles banks before g+1's ksi=0 re-inits them) so Fable's H1(init-race)/H5(boundary) NEVER fire.

**Kernel-only** — host needs no change: it already claims `occ[20]=TOTAL` tiles for the flow path
(`occ_dispatch.cpp` ~1847 `claimTotal=TOTAL`), groups are internal, `accN` from `DSWS2_ACC_N` sizes LDS (~1811).

**group is packed into STAMP high bits:** `STAMP=(group<<28)|sti`, `STI_MASK=0x0FFFFFFF` (sti<2^28 all shapes).
Every new-logic edit is gated `.if GROUPS>1`, so `ACC_N=G=6` (GROUPS=1) is **byte-identical to committed HEAD**
(verified). `ACC_N=G` makes the `G→ACC_N` swaps identical immediates.

### Edit map (occ_kernel_dsws_flow.s) — for targeted debugging
- **K0** defsyms: `GROUPS=(G/ACC_N)`, `STAMP_GSHIFT=28`, `STI_MASK`, assert `G%ACC_N==0`.
- **K1** coordinator (~1466–1547): combined cursor `= group*n_kseg + ksi`; continue while `cursor < GROUPS*n_kseg`
  (`= GROUPS<<s68`); form `STAMP=(group<<28)|(t<<shift|ksi)`. Sentinel `COORD_KSI=0xFFFFFFFF` still claims tile 0.
- **K2** compute STAMP unpack (~1580): `s41=group=STAMP>>28`; SAFEPROBE clamp `s_min s41,GROUPS-1` (brick-proof);
  `s17=sti=STAMP & STI_MASK`; then DECODE_STI.
- **K3** A-base (~1597): `actual_rowblk = group*ACC_N + local(s33)` (into s42), indexes the all-G resident-A.
- **K4** rowblk exhaustion (~1577): `s33 >= ACC_N` (== G at GROUPS=1).
- **K5** completer (~1689–1719): `RBDONE >= ACC_N`; C tile base `+= group*(ACC_N*FM*FN*1024)` (s39); store `.rept ACC_N`.
- **K7** feed (~1748) + 2 coast sites (ASTAGE ~1799, BSTAGE ~1805): `s17 &= STI_MASK` before DECODE (else group
  bits corrupt `t`). Banks indexed by LOCAL rowblk 0..ACC_N-1; C store uses the group-offset base.

## THE OPEN QUESTION (what Run 8 answers): WHY does the group-split deadlock?

`fence` never fires; whole-tile (ACC_N=6) works. It's a completion deadlock. `occ0=0` at +0.2s (fast) is the
puzzle — waves exited/retired quickly but the WG never terminated. Leading hypotheses (Run 8 frontier decides):
- **Staging deadlock:** emergent all-compute seed (`16c0a0b`) relies on *coast-feeding*; if a group super-tile's
  staging never completes (`BF<FN` or `AR<G`), all compute coasts → `RBDONE` stuck < ACC_N → DRAIN stalls.
- **Exit-barrier:** a wave never reaches `.Lflow_dead` (e.g. coordinator stuck in `.Lflow_drainwait` because
  DRAIN never reaches ASSIGN) → count-to-WAVES never closes → the retired waves spin (no watchdog) → wedge.
- **Completer/DRAIN:** some emitted super-tile never advances DRAIN.

Note: the count-to-WAVES exit barrier spin has **no deadman** — if it's the culprit, consider a watchdog escape
(s_endpgm after a timeout) so a future completion-deadlock DRAINS instead of MES-wedging (brick prevention).
