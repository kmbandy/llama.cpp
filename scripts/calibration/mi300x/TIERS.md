# ml8 calibration gauntlet — tier structure

The MI300X pod runs **calibration only** (blobs + `Y_SNR`); ml8 inference is
gfx1201-only, so PPL is run later on the R9700 against the finalists. `Y_SNR`
(the Hessian-weighted output-space error `trace((W−Q)ᵀH(W−Q)/WᵀHW)`, computed
*during* calibration — no forward pass, no ml8 kernel) is the wide-filter ranking
proxy; PPL is the final gate.

```
Tier-1 (group_size grid) ──Y_SNR rank──▶ top-3 cells
        │                                     │
        │                                     ▼
        │                          Tier-2 (top-3 × other levers)
        │                                     │
        └──────────────┬──────────────────────┘
                       ▼
              R9700: PPL on the 2–3 finalists  (vs UD-Q4_K_XL / bf16)
```

Whole gauntlet ≈ 40–60 calibrations → saturates the 8×MI300X pod (one evening,
not a day). bpv_target = 4.25 ("win both axes": smaller AND lower PPL than UD).

## Tier-1 — group_size main-effect grid  (WRITTEN: `gauntlet_tier1.json`)

12 cells = {qwen36-27b dense, qwen36-35b-a3b MoE} × the group_size grid
(gate/up ∈ {128, 64}) × (down ∈ {16, 32, 64}). Everything else fixed at the
baseline recipe (`rotation: kronecker`, `snap_centroids: e4m3`, `fit_loss: mse`,
`n_centroids: 16`, `n_samples: 32`, `seq_len: 1024`, `act_order: true`,
`heavy_rounds: 4`, `heavy_steps: 60`, `heavy_dtype: bf16`). Generated by
`gen_gauntlet_manifest.py`; ranked by per-cell `Y_SNR`.

## Tier-2 — top-3 cells × the "other levers"  (PLANNED — not yet a manifest)

Take the **top-3 tier-1 cells by Y_SNR** and cross them with the four lever
families below. Tier-2 is **data-dependent** (it needs tier-1's ranking to pick
the top-3), so it gets generated *after* tier-1 finishes — a `gen_gauntlet_tier2.py`
that takes the winning cell IDs and emits the cross. Code it while tier-1 runs.

| Lever | calibrate_ml8_paged.py knob | Tier-1 value | Tier-2 sweep |
|-------|------------------------------|--------------|--------------|
| **mag_weighted-down** | `--fit-loss` (down proj only) | `mse` | `mag_weighted` on down (`--mag-weight-p`, e.g. 5) |
| **heavy++** | `--heavy-rounds` / `--heavy-steps` | 4 / 60 | bump (e.g. 8 / 120) |
| **corpus-scale** | `--n-samples` × `--seq-len` | 32 × 1024 | ~16k tokens total (e.g. 64 × 2048) |
| **rotation** | see the rotation menu below | `kronecker` | sweep the menu |
| **AWQ rescaling** | `--awq none\|mean` + `--awq-alpha` | `none` (off) | `mean` × α ∈ {0.25, 0.5} — **but see the per-token caveat** |

### The rotation menu (the lever's sub-options)

Two mechanisms — an in-calibration per-linear rotation (`--rotation`) and a
pre-calibration model-global pass (baked into the GGUF, then calibrated with
`--rotation none`):

| Option | Mechanism | Status |
|--------|-----------|--------|
| **identity / none** | `--rotation none` | live (control) |
| **kronecker** (`kronecker_orth_sylvester`: random-orth Hₐ ⊗ Sylvester H_b) | `--rotation kronecker` | live — tier-1 baseline |
| **hadamard_full** (full Sylvester Hadamard, pow2 dims) | in the rotation blob schema as a `kind`, **not yet a live `--rotation` choice** (code = `none\|kronecker`) — needs wiring | NEEDS CODE |
| **quarot-R1 / R_resid** (model-global residual-stream Hadamard; input-side + output-side + MoE expert-axis) | pre-pass `rotate_model_quarot.py` → `…-quarotR1.gguf`, then calibrate `--rotation none` | exists; **γ-absorption bug under bisection (MAD-244 #104)** — must be green before it's a live lever |
| *(deferred)* R2 (KV-side), R3/R4 (online Hadamard) | — | designed, not built; out of scope for this gauntlet |

## Honest caveats (from the 2026-05-29 35B scorecard)

On the **35B MoE at uniform 4-bit**, several of these levers tested weak/dead:
AWQ dead, mag_weighted *hurts*, reweighted-Hessian dead, **rotation "spent"**
(kronecker already near codebook-optimal; the +0.046 gap to UD did not fall to
any one-shot/light lever). So tier-2's value is primarily:

1. **Confirming on 27B *dense*** (a different regime than the MoE where most of
   that scorecard was measured), and
2. The **full-model-coverage context** (Design A, the new 3-tier FP8/4-bit map)
   may shift which levers matter vs the FFN-only uniform-4bit runs.

Don't assume tier-2 will move the needle — it's a confirmation/expansion sweep,
and the rotation lever specifically needs the quarot-R1 γ-absorption bug fixed
(and `hadamard_full` wired) before two of its four options are even runnable.

### Why AWQ is dead here — and why it predicts the rotation lever too (MAD-256 #1, 2026-05-29)

AWQ was the *top untried bpv-neutral lever* in the strategy, then the offline rig
(`awq_sweep.py` / `down_proj_rig.py`, Qwen3.6-35B-A3B, L0/L20, 64 busiest experts,
gs64/nc16/e4m3) killed it: gate +0.27/+0.07 dB, up +0.23/+0.05, down +0.09/+0.09
(L0/L20) peaking at **α≈0.25**, all going **negative past α~0.25–0.5**.

**Root cause (well-grounded, the load-bearing insight):** the SwiGLU down_proj
intermediate `silu(gate·x)·(up·x)` is fat-tailed with **median** per-channel
kurtosis 121–183 (max ~6000–8200; gaussian = 3). The *median* being huge (not just
the max) means **nearly all** channels are fat → the signature of **per-token**
outliers (a few outlier tokens spike across many channels), NOT per-channel
outliers. AWQ scales **per-channel**, so when every channel is ~equally fat its
scale vector is ~uniform → near no-op. Independently confirmed by MAD-214 KV work
("Qwen K outliers more per-token than per-channel; Hadamard helped only ~12%"). So
**per-token-dominant outliers are a consistent Qwen-family property across KV and
FFN.**

**The unifying implication for tier-2:** *per-channel* methods have little headroom
on this model — that's **AWQ AND the residual-stream-Hadamard / QuaRot-R1 rotation
option** (both per-channel). The levers that *match* per-token structure, and thus
carry the real expected value, are:

- **`mag_weighted` fit-loss** — up-weights high-|sample| outlier-token contributions
  in Lloyd-Max (per-sample/token aware), and
- **finer `group_size` on down** — per-group scale adapts to local magnitude
  regardless of channel/token alignment (small bpv cost; down_proj is the
  worst-quantizing matrix, baseline Y_SNR 20.6/22.5 vs gate/up 32/24, so most
  headroom IF the lever matches the structure).

So in tier-2, treat **AWQ and quarot-R1 as low-prior confirmation cells** (cheap to
include for the 27B-dense / full-coverage regime, but don't bank on them), and put
the search budget on **mag_weighted-down + group_size-down**. Keep `kronecker`
(per-linear, already the near-optimal baseline) as the rotation default.

## When we code tier-2 (while tier-1 runs)

- `gen_gauntlet_tier2.py`: input = the 3 winning tier-1 cell IDs (+ their
  group_size); output = `gauntlet_tier2.json` = the 3 cells × the lever sweep,
  each cell carrying its computed avg bpv (must still honor 4.25).
- Gate the **rotation** sub-sweep on: quarot-R1 equivalence green
  (`test_quarot_r1_equivalence.py`) + `hadamard_full` added to `--rotation`
  choices. Until then, the rotation lever runs only `{none, kronecker}`.
- `run_gauntlet.py` already passes `job["rotation"]` → `--rotation`; the
  quarot-R1 option additionally needs a pre-pass step (rotate the bf16 GGUF
  once, point the cell at the rotated GGUF, set `--rotation none`).
