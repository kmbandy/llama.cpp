# SP1 — turbo4_0 KV on Vulkan contiguous FA — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `turbo4_0` (4-bit PolarQuant + RHT) as a symmetric KV cache type on the `ggml-vulkan` contiguous flash-attention path, matching the CUDA implementation numerically.

**Architecture:** Three device pieces — the `GGML_OP_TURBO_WHT` Vulkan op (Task 1, already done; used graph-level for **Q-forward** and **attention-output-inverse** rotation only), a **self-contained** f32→turbo4_0 cpy/quantize shader (Task 2; bundles norm → forward WHT → centroid → norm-correction, matching the CPU `from_float`), and a centroid×norm dequant in the FA shader (Task 3). **K/V rotation is bundled inside the cpy/quantize — it is NOT graph-level.** This matches the non-paged contiguous-FA dataflow: `cpy_k`/`cpy_v` (`src/llama-graph.cpp:2759-2760`) lower to the generic dst-quant copy → the rotating `from_float`; graph-level `ggml_turbo_wht` touches only Q (`:2780`, forward) and the output (inverse). FA reads in the rotated domain (`<Q_rot,K_rot> = <Q,K>` since WHT is orthogonal). The CPU/CUDA *non-paged* path is the reference to translate, not reuse (GLSL vs CUDA C++). **(Note: the CUDA *paged* `mt_scatter` path is rotation-free + remaps to TURBO4_64 — that is a DIFFERENT code path and NOT the SP1 target; do not use it as a reference.)**

**Tech Stack:** C++ (Vulkan API host code in `ggml-vulkan.cpp`), GLSL compute shaders → SPIR-V (`ggml/src/ggml-vulkan/vulkan-shaders/`), `test-backend-ops` for per-op correctness, `llama-perplexity` for end-to-end parity.

**Spec:** `docs/superpowers/specs/2026-06-28-sp1-turbo4-vulkan-fa-design.md`

## Task 1: `GGML_OP_TURBO_WHT` Vulkan backend (forward + inverse)

> **CORRECTION (2026-06-29):** The op is `GGML_OP_TURBO_WHT` (already in `ggml.h:584`, `ggml.c:6456`), **not** a new `GGML_OP_FWHT`. It already has working **CPU + CUDA + Metal** backends — SP1 adds **only the Vulkan backend**. Do **NOT** create a new op and do **NOT** touch `ggml.c`/`ggml.h`. (`fwht.cu` is an unrelated MUL_MAT-Hadamard-hint op — ignore it.)

The linchpin — used 4× (Q/K/V pre-rotate, output inverse). The public op is `ggml_turbo_wht(ctx, a, direction, group_size, scale)`: per `group_size`-element group along `ne[0]`, `sign1 → WHT butterfly → sign2 → normalize`. `direction` 0=forward (`signs1 → WHT → signs2`), 1=inverse (`signs2 → WHT → signs1`). Optional per-channel `scale` (InnerQ scale_inv) in `src[1]`: forward multiplies BEFORE signs+WHT, inverse multiplies AFTER WHT+signs. `op_params`: `direction` @ offset 0, `group_size` @ offset `sizeof(int)`.

**Reference to translate (do not reuse — separate backend):**
- CUDA kernel `k_turbo_wht_f32<direction, group_size>` in `ggml/src/ggml-cuda/turbo-wht.cu` — one block per group, `group_size` threads, `__shared__ float x[group_size]`, `WHT_STAGE(h)` butterfly for `h=1,2,…,group_size/2` with `__syncthreads()` between stages. This is a near-verbatim GLSL translation target.
- CPU oracle (what `test-backend-ops` compares against): `ggml_compute_forward_turbo_wht_f32` in `ggml/src/ggml-cpu/ops.cpp:10835`.
- **Sign tables (verbatim source of truth — port, do not re-derive):** `turbo_wht_s1[128]` / `turbo_wht_s2[128]` at `ggml/src/ggml-cpu/ops.cpp:10832-10833` (identical to CUDA `TURBO_WHT_SIGNS1/2`). `s_first = (direction==0)?s1:s2`, `s_second = (direction==0)?s2:s1`. Normalize by `1/sqrt(group_size)`.

## Task 2: f32→turbo4_0 cpy/quantize shader (SELF-CONTAINED — bundles the WHT)

> **CORRECTION (2026-06-29, reconciliation-verified):** This shader is **NOT rotation-free**. On the
> non-paged contiguous-FA path SP1 targets, K/V rotation is bundled inside the quantizer (there is no
> graph-level WHT on K/V). The shader must replicate the registered CPU `from_float` exactly. The CUDA
> `quantize_f32_turbo4_0_block` (paged helper, rotation-free, no norm) is the WRONG reference — ignore it.

**Oracle to replicate (verbatim algorithm):** `quantize_row_turbo4_0_ref`
(`ggml/src/ggml-turbo-quant.c:426-535`, the `#if TURBO4_USE_4BIT` branch). Per 128-element block:
1. `norm = sqrt(Σ src[i]²)` over the 128 values; `normalized[i] = src[i]/norm` (zeros if `norm ≤ 1e-10`).
2. **Forward WHT** on `normalized` via the signed 128-pt transform = Task 1's forward `TURBO_WHT`
   (`s1 → butterfly h=1..64 → ×(1/sqrt(128)) → s2`; sign tables `turbo_wht_s1/s2[128]`,
   `ggml/src/ggml-cpu/ops.cpp:10832-10833`; `turbo_cpu_fwht` in `ggml-turbo-quant.c:216`).
3. `indices[i] = nearest_centroid_4bit(rotated[i])` via the `TURBO_MID_4BIT[15]` ladder.
4. **Norm correction:** `recon_norm = sqrt(Σ TURBO_CENTROIDS_4BIT[indices[i]]²)`;
   `corrected_norm = (recon_norm > 1e-10) ? norm/recon_norm : norm`. Store `norm = fp16(corrected_norm)`.
5. Nibble-pack `indices` into `qs[64]` (`qs[i/2] |= (idx & 0xF) << ((i%2)*4)`); `rnorm = fp16(0)`.

This is the SAME WHT as Task 1 — so the cpy shader can reuse Task 1's forward-WHT shader body, then add
the two reductions (norm, recon_norm), the centroid ladder, and the norm correction.

```glsl
    FLOAT_TYPEV4 c = FLOAT_TYPEV4(                                               \
        TURBO_CENTROIDS_4BIT[(BUF.data[b].qs[(i0  )/2] >> (((i0  )%2)*4)) & 0xF],\
        TURBO_CENTROIDS_4BIT[(BUF.data[b].qs[(i0+1)/2] >> (((i0+1)%2)*4)) & 0xF],\
        TURBO_CENTROIDS_4BIT[(BUF.data[b].qs[(i0+2)/2] >> (((i0+2)%2)*4)) & 0xF],\
        TURBO_CENTROIDS_4BIT[(BUF.data[b].qs[(i0+3)/2] >> (((i0+3)%2)*4)) & 0xF]);\
    return c * nm;                                                               \
}
```

## Task 4 Results (2026-06-29) — turbo4 KV enabled end-to-end on Vulkan

Implemented + verified on Vulkan0 (RX480 RADV POLARIS10, wave64); model
LFM2.5-8B-A1B-UD-Q5_K_S, flash-attn on, symmetric K/V.

**Step 1 — enable.** The blocker was not a missing switch: the KV-cache *write*
scatters rows via `GGML_OP_SET_ROWS`, which had no turbo4_0 quantizer, so load
aborted at `graph_reserve` ("cache_k_l2 … cannot run the operation (SET_ROWS)").
Added a turbo4_0 set_rows quantizer + dispatch + `supports_op`. Server then loads
and `/completion` returns coherent output ("The capital of France is Paris …").

**Step 2 — PPL parity (vs f16 on the same backend; CUDA turbo4 is paged-only, so
no contiguous CUDA reference exists).** wikitext-2 test, identical config except KV:

| KV (-c 512, 20 chunks) | PPL |
|---|---|
| turbo4 | 32.73 ± 1.66 |
| f16    | 33.08 ± 1.68 |

Δ = −0.36 (−1.1%), well within the ±1.66 noise band — turbo4 KV is quality-neutral
vs f16. (High absolute PPL is the instruct model on raw wikitext over few chunks;
the delta is the valid signal.)

**Step 3 — perf (llama-bench, pp512 / tg128 t/s):**

| KV | pp512 | tg128 |
|---|---|---|
| f16    | 624.7 | 93.8 |
| q4_0   | 621.7 | 91.9 |
| turbo4 | 555.8 | 88.8 |

turbo4 is within ~11% pp / ~5% tg of f16 (the FWHT rotation + 4-bit quant cost),
buying a 4× smaller KV cache — and matches/beats the custom ROCm path (~500-600 pp,
~50-60 tg). **Perf-critical lesson:** the first set_rows quantizer was a *serial*
one-thread-per-block shader whose per-thread `[128]` arrays spilled out of registers
→ SET_ROWS 290 µs/call (67× f16) → pp512 156 / tg128 10.6. Replaced with a
**cooperative** 128-thread/block shared-memory shader (`set_rows_f32_turbo4_0.comp`,
commit 36ae97ec4) → SET_ROWS 9.2 µs, pp512 560, tg128 87. Always benchmark a
KV/attention/quantizer change; op-correctness tests do not catch perf cliffs.

**Build infra:** `build-vk.sh` rewritten to size MemoryMax/MemoryHigh/-j adaptively
from free RAM (the old MemoryHigh=5G throttled the ~5G ggml-vulkan.cpp TU into swap).
