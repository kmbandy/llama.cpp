## 5. The distributed split — where it stands

Spec: `docs/superpowers/specs/2026-07-25-two-process-layer-split-design.md`
(read §0 VERIFIED first — it supersedes the numbers in §2/§3 of that doc).

**Corrections to the old roadmap, both verified:** llama.cpp **does** have
pipeline parallelism (`llama-cparams.h:48`, live), and RPC **can** express layer
placement (`llama-model.cpp:1603-1622` gives contiguous per-device ranges from
`--tensor-split`). The real blockers are that the pager can't span devices
(`llama.cpp:145-155` throws) and RPC has `caps.async=false, caps.events=false`.

**Design: two processes, one pager each, an activation channel.** Not
RPC-as-a-device, no scheduler changes. Justified because decode is ~333 ms/token
and the payload is small, so one synchronous round trip per token costs <1%.

**Verified numbers:**
- **Payload = 64 KiB/token f32** (`n_embd 4096 × hc_mult 4 × 4`). The residual
  really is 4-stream; there is no collapse inside the stack, only at the head.
- **43 executed layers**, not 44 (`blk.43` is the MTP block, loaded not run).
- **Legal cuts: `ib ∈ [3, 43]`.** Below 3, hash layers need raw token IDs.
  Mid-layer cuts are **forbidden** (`build_hc_pre` produces `post`/`comb` that
  `build_hc_post` consumes).
- 4096-token prefill = 256 MiB f32, chunkable.

**THE REMAINING WORK — the inject path.** `t_layer_inp` /
`llama_get_embeddings_layer_inp` taps a boundary residual and is production code
(it feeds the DFlash drafter). **There is no injection counterpart** — no API, no
graph path to *start* a `deepseek4` pass from a supplied residual at layer K,
verified by absence. Template to copy: `src/models/dflash.cpp:97-99,115-116`.

**Open decisions for kmbandy** (none are mine to make):
1. **Where does the cut go?** Storage says ~31%; compute says less (1070/480 are
   far weaker). My recommendation after the CUDA pool-size finding: **20-25%**,
   tune up. The 1070's page pool would be ~6 GB vs the R9700's 23 GB.
2. **Which end samples?** Recommend **stage 0** — 259 KiB/token of logits is free
   at these speeds and keeps sampler/grammar/slot state undivided.
3. **How is the GGUF split?** Physical split is the only option that fits 2026's
   drive. Shard 4 (18.3 GB, 91% compressible, likely mostly inert) can go
   anywhere.
4. **What owns the API?** Presumably stage 0 runs the server, stage 1 headless —
   but launching/supervising stage 1 and its relation to the live router is
   undecided.

## 6. The CUDA port — what was done and how it was verified

**Scope was established by object-size diffing against the working HIP build**,
which localised it to two files instead of the "7 files / 38 guard sites" a
source read suggested:

| TU | HIP | CUDA before | CUDA now |
|---|---|---|---|
| `wp-gpu-transport.cpp` | 11752 | **2800 (stub)** | **13976** |
| `wp-eval-cb.cpp` | 84936 | **28672** | **84432** |
| `wp-file-io.cpp` | 46384 | 36464 | **54400** (liburing installed) |
| `wp-pager.cpp` | 221960 | 226760 | 238848 — already portable |
| `wp-file-io-p2p.cpp` | 45952 | 1296 | 1296 — **stub, correct**, no ReBAR |

**HIP is unchanged BY CONSTRUCTION, and I verified the construction:**
- every preprocessor change is a pure widening
  `#if defined(GGML_USE_HIP)` → `... || defined(GGML_USE_CUDA)`
- the shim's HIP branch is byte-identical to the `#include <hip/hip_runtime.h>`
  it replaced
- **zero non-preprocessor code changes** (the only non-directive diff lines are a
  blank line moving)
- CMake's `if(GGML_HIP)` branch untouched; a new `if(GGML_CUDA)` block added

**The review catch worth remembering:** the shim mapped `hipStreamGetDevice` →
`cudaGetDevice`. Those answer different questions — stream's device vs
currently-active device. At the sole call site `ScopedHipDevice` had already set
the active device to `target_device`, so the guard became **tautologically true
and could never fire**. It exists to catch a compute stream on the wrong device.
A safety check that always passes is worse than an absent one. `cudaStreamGetDevice`
is CUDA 12.8+; this box is 12.0. Fixed in `b570c75e8` — mapping removed, call site
skips the check explicitly on CUDA with the gap documented.
**Lesson: a name that maps 1:1 is not semantics that map 1:1.**

## 7. Measured results — do not re-measure

**Pipelined promotion (clean box, 3 rounds, order alternated):** ON won all three.
Means ON 2.734 vs OFF 2.655 = **+3.0%**. Mechanism, tight in both arms:
promotion overhead **846.4 → 281.1 ms (−565 ms)**; `jobs` 274.7/280.2/276.8 →
4.4/4.5/4.5; `promo` 565.0/575.6/567.0 → `fence` 277.3/277.0/275.7.

**Why this one converted when four others didn't:** the others shrank phase time
already overlapped with compute. This removes a **serialization that blocked NVMe
submission** — promotions no longer complete before the cold-miss batch is
submitted. It doesn't make I/O faster; it stops promotion delaying I/O.

**Transports (4 GB tier):** HOST 3.09-3.14 tok/s / 4.39 GB/s · P2P ~2.73 /
2.92 · serial 1.958 / 1.70. **HOST wins.** P2P needs SAM/ReBAR so it can only run
on main — the box where it loses.

**In-flight depth is pinned at 5.29 in every arm all day** — 20025 pages / 3310
batches = **6.05 pages per `ensure_batch` call**. Queue depth and iowq are dead
knobs. The only route past it is more pages per step (prefetch/MTP), and the KG
records xlayer prefetch as moving in-flight only 6.12 → 6.38.

**The model is incompressible outside shard 4** (111/0/0/1747 encoded extents), so
uncompressed storage costs nothing anywhere.

## 8. Retractions from today — do not resurrect these

1. **"~+6% decode from zero-copy"** — did not occur; tier is throughput-neutral.
2. **"The RAM tier is a net loss"** — retracted, one underpowered run.
3. **P2P mapping-churn hypothesis** — called dead off 256/1024, then alive at
   4096; both were below a threshold. Then the whole thing retracted (§below).
4. **"Master is safe"** after gating — false; the gate introduced a crash.
5. **"3× pipelining regression"** — an artifact of another user's container build
   saturating the CPUs. There was no regression.
6. **BAR-contention mechanism** — fence measures 289 ms, not 120 s.
7. **ABI-mismatch explanation for the crash** — wrong; all `wp-pager.h` consumers
   were current.
8. **Window cache 4096 is "the one real gain"** — it is **net harmful**: best read
   bandwidth, worst throughput (1.817 vs ~2.73). The **full-pool host map**
   recommendation is withdrawn with it — same mechanism amplified.
9. **`tier_promotion_h2d_ms`** — deleted; it reported ≈ `read_wait` in both modes.
10. **"llama.cpp has no pipeline parallelism / RPC cannot express it"** — both
    false (§5).

**The crash sequence, worth internalising:** a regression that didn't exist →
a gate to protect against it → the gate dropped a `borrow()` → null passed to
`hipMemcpyAsync` → deterministic abort in HOST+tier, the config we actually ship.
Found only by going looking for damage from the non-existent problem.

## 9. Traps

- **Check the box state at BOTH ends of a sweep.** Two retractions came from
  measuring through someone else's load. kmbandy's ruling: *"stop discounting
  readings from a machine that's doing other things — that's the real world."*
  The answer is experimental **design**, not waiting for quiet: **alternate arm
  order every round**, take the within-round comparison.
- **Phase counters are primary; tok/s is directional.** Counters replicate to
  ~1-2%; tok/s swings 8-17% on identical configs.
- **n=3 minimum.** n=1 and n=2 each produced a retraction today.
- **Never compare arms across sessions.**
- **Bandwidth can move opposite to total time** — `io_gb_s` and read_wait improved
  while wall-clock got worse, three separate times.
- **Build the FULL target set.** A single-target build left a day-old
  `llama-server` while `libllama.so` was current; one object's timestamp proves
  nothing about the binary under test.
- **Codex tasks don't reliably notify.** Check the session rollout mtime at
  `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`, never the process (the host is a
  persistent daemon). `codex-rescue` forwards **one** invocation per dispatch — a
  `SendMessage` resume does **not** start a new run.
- **mad-lab-main's login shell is fish.** Wrap remote commands as
  `ssh mad-lab-main bash /tmp/script.sh`; `$(...)`, parens, `<` and apostrophes
  break inside quoted remote commands. Use `git commit -F`, never `-m` with
  apostrophes.
- **Never `git checkout/restore/stash/reset/add -A/commit -a`** in either tree.
  When merging, resolve **hunk-by-hunk** — `git checkout --theirs` takes the whole
  file and silently discards auto-merged changes in it.
- **`~/host_cache.sh`'s `killsweep.sh llama-server` would kill the live router.**
- **`pgrep -f <pattern>` self-matches your own shell.**
